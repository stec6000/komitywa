# Hardening `run_weekly_research` — SUMMARY

## What was done

Cztery niezależne zabezpieczenia w `content/management/commands/run_weekly_research.py`:

1. **`time.sleep(60)` między call 1 a call 2** — safety net na rate limit Tier 1 Anthropic (30k input tokens/min). Call 1 z web searchem zjada większość budżetu minuty; 60s przerwy gwarantuje czyste okno dla call 2. Emituje NOTICE, żeby operator widział pauzę. Pomija się przy `--retry-format`.

2. **`JSON_STRICTNESS_ADDENDUM` (module-level constant)** — runtime addendum doklejany do `FORMAT_PROMPT` przed call 2. Treść instruuje Sonneta, by zwrócił WYŁĄCZNIE prawidłowy JSON i escapował cudzysłowy wewnątrz stringów. Powód: zaobserwowane fail-e — Sonnet 4.6 przy polskich tekstach (np. `„brownie"`) potrafi pominąć escape. **`FORMAT_PROMPT` constant pozostaje VERBATIM nietknięty** — addendum jest doklejany w runtime.

3. **`Command._call_format` helper z auto-retry** — wydzielony helper robi call 2, strippuje markdown fences, próbuje `json.loads`. Na `JSONDecodeError`:
   - Loguje WARNING z `pos`, `lineno`, `colno` i 100-char kontekstem
   - Czeka 60s (rate limit safety)
   - Ponawia ten sam prompt (addendum już jest)
   - Drugi parse fail → `CommandError` z fragmentami obu błędów → flow w `handle()` zapisuje `status=failed`, `error_message`

4. **Flaga `--retry-format`** (CLI) — mutually exclusive z `--force`:
   - Pomija call 1 (drogi, web search)
   - Ładuje istniejący `WeeklyResearch.raw_research` z DB
   - Robi tylko call 2 (z normal retry logic)
   - Walidacje: brak rekordu → CommandError, pusty `raw_research` → CommandError, jednoczesny `--force` → CommandError
