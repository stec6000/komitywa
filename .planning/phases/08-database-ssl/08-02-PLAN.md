The operator must SSH into the MyDevil server and execute the following steps. Claude cannot perform these -- they require direct server access.

**Prerequisite:** DNS A record for kuchennakomitywa.pl must point to the MyDevil server IP. If there is an AAAA (IPv6) record, remove it first -- Let's Encrypt on MyDevil does not support IPv6 validation.

**Step 1: Get the server IP address**
```bash
ssh mydevil
devil www list
# Note your IP address from the output
```

**Step 2: Generate Let's Encrypt certificate**
```bash
devil ssl www add YOUR_IP le le kuchennakomitywa.pl
# Replace YOUR_IP with the IP from Step 1
# This generates and installs the Let's Encrypt certificate
# MyDevil auto-renews this certificate
```

**Step 3: Verify certificate is installed**
```bash
devil ssl www list
# Should show kuchennakomitywa.pl with a Let's Encrypt certificate
```

**Step 4: Test HTTPS works before enabling sslonly**
Open browser: `https://kuchennakomitywa.pl` -- site should load with valid certificate (green padlock).

**Step 5: Enable HTTPS-only (redirect all HTTP to HTTPS)**
```bash
devil www options kuchennakomitywa.pl sslonly on
```

**Step 6: Verify HTTP redirects to HTTPS**
```bash
curl -I http://kuchennakomitywa.pl
# Should show 301 redirect with Location: https://kuchennakomitywa.pl/
```

<task type="checkpoint:human-action" gate="blocking">
  <name>Task 2: Activate security env vars, configure CSRF_TRUSTED_ORIGINS, set up keep-alive cron</name>
  <read_first>backend/settings.py, .env.example</read_first>
  <action>
The operator must SSH into the MyDevil server. These are production .env changes and cron configuration.

**Step 1: Update production .env with security settings**
```bash
cd ~/domains/kuchennakomitywa.pl
nano .env
```

Add or uncomment these exact lines in the .env file:
```
SECURE_SSL_REDIRECT=True
SESSION_COOKIE_SECURE=True
CSRF_COOKIE_SECURE=True
SECURE_HSTS_SECONDS=3600
SECURE_HSTS_INCLUDE_SUBDOMAINS=True
SECURE_HSTS_PRELOAD=False
CSRF_TRUSTED_ORIGINS=https://kuchennakomitywa.pl,https://www.kuchennakomitywa.pl
```

IMPORTANT: Start with `SECURE_HSTS_SECONDS=3600` (1 hour), NOT 31536000 (1 year). HSTS is cached by browsers and cannot be easily undone. Only increase to 31536000 after confirming everything works for at least a day.

Note: `SECURE_SSL_REDIRECT=True` is a Django-level safety net. The `sslonly on` from Task 1 handles the actual redirect at Apache level. If you encounter a redirect loop (ERR_TOO_MANY_REDIRECTS), set `SECURE_SSL_REDIRECT=False` -- the server-level redirect is sufficient. `SECURE_PROXY_SSL_HEADER` is already set correctly in settings.py (line 244) to detect proxied HTTPS.

**Step 2: Restart the application**
```bash
devil www restart kuchennakomitywa.pl
```

**Step 3: Verify POST forms work under HTTPS**
- Open `https://kuchennakomitywa.pl/admin/login/` and log in. If login succeeds without CSRF 403 error, CSRF_TRUSTED_ORIGINS is working correctly.
- Test newsletter signup form if available.

**Step 4: Verify cookie security flags**
After logging in to /admin/:
- Open browser DevTools (F12) -> Application -> Cookies
- Find the `sessionid` cookie:
  - `Secure` flag must be checked (True)
  - `HttpOnly` flag must be checked (True) -- this is Django's default
- Find the `csrftoken` cookie:
  - `Secure` flag must be checked (True)

Alternative CLI check:
```bash
curl -v https://kuchennakomitywa.pl/admin/login/ 2>&1 | grep -i "set-cookie"
# Should show: Secure; HttpOnly in cookie attributes
```

**Step 5: Set up keep-alive cron job**
```bash
crontab -e
```

Add this line at the end of the crontab:
```
0 */12 * * * /usr/local/bin/curl -s https://kuchennakomitywa.pl > /dev/null 2>&1
```

This pings the site at minute 0, every 12 hours (00:00 and 12:00), preventing MyDevil's 24h auto-shutdown of idle Passenger processes.

**Step 6: Verify cron job is saved**
```bash
crontab -l
# Should show the curl ping line
```
