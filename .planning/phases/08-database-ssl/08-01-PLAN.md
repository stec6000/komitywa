  <action>
Add the PostgreSQL adapter to requirements.txt. Append this exact line after the existing dependencies:

```
psycopg[binary]>=3.3,<4
```

This is Django 5.2's preferred PostgreSQL adapter. The `[binary]` extra is required because MyDevil shared hosting lacks libpq-dev for building from source. Do NOT use psycopg2 or psycopg2-binary (legacy, will lose Django support).

After adding, run locally:
```bash
pip install -r requirements.txt
python manage.py test --verbosity=0
python manage.py check --deploy
```

The test suite must still pass -- psycopg[binary] is additive and does not affect SQLite-based local development.

<task type="checkpoint:human-action" gate="blocking">
  <name>Task 2: Create PostgreSQL database, run migrations, create superuser on MyDevil</name>
  <read_first>deploy.sh, .env.example, backend/settings.py</read_first>
  <action>
The operator must SSH into the MyDevil server and execute the following steps. Claude cannot perform these -- they require direct server access.

**Step 1: Create PostgreSQL database**
```bash
ssh mydevil
devil pgsql db add komitywa
# Note the password -- you will need it for DATABASE_URL
# If you need to reset the password:
devil pgsql passwd komitywa
```

**Step 2: Find the PostgreSQL server address**
```bash
devil pgsql list
# Look for the host address, format: pgsqlX.mydevil.net
```

**Step 3: Update production .env with DATABASE_URL**
```bash
cd ~/domains/kuchennakomitywa.pl
nano .env
```

Uncomment and fill in the DATABASE_URL line:
```
DATABASE_URL=postgres://komitywa:YOUR_PASSWORD@pgsqlX.mydevil.net:5432/komitywa
```

Replace:
- `YOUR_PASSWORD` with the password from Step 1 (use only alphanumeric chars + `-_` to avoid URL encoding issues)
- `pgsqlX` with the actual server address from Step 2

**Step 4: Deploy (pulls new code with psycopg, installs deps, runs migrations)**
```bash
bash deploy.sh
```

This will:
- Pull latest code (with psycopg[binary] in requirements.txt)
- Install psycopg[binary] in the virtualenv
- Run `python manage.py migrate --noinput` against PostgreSQL
- Collect static files
- Restart the app

**Step 5: Verify migrations applied**
```bash
source ~/.virtualenvs/komitywa/bin/activate
python manage.py showmigrations --list | grep -c "\[X\]"
# Should show all migrations as applied (marked with [X])
```

**Step 6: Create superuser**
```bash
python manage.py createsuperuser
# Enter email and password when prompted
```

**Step 7: Verify admin access**
Open browser and navigate to `http://kuchennakomitywa.pl/admin/` (HTTP for now -- HTTPS comes in Plan 02).
Log in with the superuser credentials created in Step 6.
