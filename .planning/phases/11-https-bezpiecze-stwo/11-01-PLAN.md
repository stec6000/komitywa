    Alternatywnie przetestuj formularz newslettera lub checkoutu.

    **Test 4 — HTTPS-04: Cookie flags Secure + HttpOnly**
    W przeglądarce: zaloguj się na konto → DevTools (F12) → Application → Cookies → kuchennakomitywa.pl. Sprawdź:
    - `sessionid`: kolumna "Secure" = zaznaczone ✓, "HttpOnly" = zaznaczone ✓
    - `csrftoken`: kolumna "Secure" = zaznaczone ✓ (HttpOnly może być niezaznaczone — to normalne)

    **Test 5 — HTTPS-05: Security headers**

<threat_model>
## Trust Boundaries

| Granica | Opis |
|---------|------|
| Browser → Apache | Niezaufany ruch przychodzący; Apache terminuje TLS |
| Apache → Django (Passenger) | X-Forwarded-Proto header — Django ufa temu nagłówkowi przez SECURE_PROXY_SSL_HEADER |
| Django → przeglądarka (cookies) | Cookies sesji i CSRF — muszą mieć Secure+HttpOnly żeby nie wyciekły przez HTTP |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-01 | Information Disclosure | sessionid cookie przez HTTP | mitigate | SESSION_COOKIE_SECURE=True — cookie nie jest wysyłane przez HTTP; ASVS V3.4.1 |
| T-11-02 | Spoofing / Tampering | CSRF — żądania z innych origin przez POST | mitigate | CSRF_TRUSTED_ORIGINS zawiera https://kuchennakomitywa.pl; CSRF_COOKIE_SECURE=True; ASVS V4.2.2 |
| T-11-03 | Tampering | Clickjacking — strona osadzona w iframe | mitigate | X_FRAME_OPTIONS="DENY" — zawsze włączone w settings.py; ASVS V14.4.7 |
| T-11-04 | Tampering | MIME sniffing — przeglądarka interpretuje zasoby jako inny typ | mitigate | SECURE_CONTENT_TYPE_NOSNIFF=True — zawsze włączone; ASVS V14.4.2 |
| T-11-05 | Tampering | Downgrade attack — wymuszenie HTTP po HSTS | mitigate | SECURE_HSTS_SECONDS=31536000 + includeSubDomains + preload; ASVS V9.1.1 |
| T-11-06 | Information Disclosure | Wygasły certyfikat TLS | accept | Certyfikat Let's Encrypt ważny do 2026-07-09; MyDevil auto-renew lub ręczne `devil ssl letsencrypt`; monitoring w zakresie Fazy 12 |
| T-11-07 | Information Disclosure | Double-redirect loop przez SECURE_SSL_REDIRECT=True na MyDevil | mitigate | SECURE_SSL_REDIRECT=False (Apache obsługuje redirect); udokumentowane w .env.example z komentarzem |
</threat_model>
