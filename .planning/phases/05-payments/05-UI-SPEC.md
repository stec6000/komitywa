## Component Inventory

Phase 5 introduces 3 new page templates and modifies 1 existing template. All are status/result pages with centered layout — no complex component grids.

### 1. Payment Return Page (`shop/p24_return.html`)

Shown when user returns from Przelewy24 after completing payment. Per D-05: shows a pending message regardless of actual order status (webhook may not have arrived yet).

```
[.kk-section]
  [.container.text-center.py-5]
    [bi-hourglass-split icon — 64px, --kk-sage]
    [h1 "Dziękujemy za zamówienie!"]
    [p body text — order pending message]
    [p.small — order number reference]
    [.kk-btn-primary "Wróć na stronę główną" → /]
[/.kk-section]
```

- Layout: centered single column, max-width 600px (`mx-auto`)
- Icon: `bi-hourglass-split` at 64px, `color: var(--kk-sage)`
- Heading: Lora 28px 700, `--kk-olive-dark`
- Body: Nunito 16px 400, `--kk-text`
- Order reference: Nunito 14px 400, `--kk-text-light`, format "Numer zamówienia: #123"
- CTA button: `.kk-btn-primary`, margin-top 24px

### 2. Payment Failure/Cancel Page (`shop/p24_cancel.html`)

Shown when user cancels payment or payment fails. Per D-06: restores cart from snapshot and redirects to checkout. This page is the intermediate display before redirect, or shown if cart restoration fails.

```
[.kk-section]
  [.container.text-center.py-5]
    [bi-exclamation-triangle icon — 64px, #DC3545]
    [h1 "Płatność nie powiodła się"]
    [p body text — failure message + retry instruction]
    [.kk-btn-primary "Spróbuj ponownie" → /zamowienie/]
    [.kk-link-arrow "← Wróć do sklepu" → /sklep/]
[/.kk-section]
```

- Layout: centered single column, max-width 600px (`mx-auto`)
- Icon: `bi-exclamation-triangle` at 64px, `color: #DC3545`
- Heading: Lora 28px 700, `color: #DC3545` (not `--kk-olive-dark` — signals error)
- Body: Nunito 16px 400, `--kk-text`
- Primary CTA: `.kk-btn-primary` "Spróbuj ponownie", margin-top 24px
- Secondary link: `.kk-link-arrow`, margin-top 16px, block display

### 3. Modified Checkout Flow (update `shop/checkout.html`)

Phase 4 checkout form already exists. Phase 5 changes the form action behavior: instead of redirecting to a static confirmation page, the POST now registers a P24 transaction and redirects the user to the external Przelewy24 payment page. The template itself requires minimal visual changes:

- **Button text remains:** "Przejdź do płatności" (already correct from Phase 4)
- **No spinner/loading state needed:** The form submit triggers a server-side redirect (HTTP 302) to P24 — browser handles the redirect natively
- **No visual template changes required** — the view logic changes, not the template

### 4. Modified Confirmation Page (update `shop/checkout_confirm.html`)

The Phase 4 stub confirmation page is replaced by the new `p24_return.html` template (Component 1 above). The existing `checkout_confirm.html` template is no longer used in the payment flow. It may be removed or repurposed.

## Accessibility Requirements

- Status page icons: `aria-hidden="true"` on all decorative Bootstrap Icons (hourglass, check-circle, exclamation-triangle).
- Heading hierarchy: single `<h1>` per status page, no subheadings needed.
- CTA buttons: clear, descriptive text — no "click here" patterns.
- Failure page: both CTA and secondary link must be keyboard-navigable (tab order: primary CTA first, then secondary link).
- Color contrast: `#DC3545` on `#FDFBF7` background passes WCAG AA (contrast ratio 4.6:1).
- Screen reader: status pages should be self-explanatory from heading + body text alone. Icons are decorative only.

---

## Implementation Pitfalls

1. **Return page must not check order status:** Per D-05, the return URL page always shows the pending/thank-you message regardless of whether the webhook has arrived. Do NOT query `order.status` to conditionally render success/pending. The webhook is asynchronous.
2. **Cart restoration timing:** On payment failure (cancel URL), the view must restore cart from `Order.cart_snapshot` into `request.session["cart"]` BEFORE rendering the cancel page or redirecting. Otherwise user sees empty cart on retry.
3. **Polish diacritics in email copy:** All email subject lines and body text must use proper Polish characters (ą, ę, ś, ć, ź, ż, ó, ł, ń). The Phase 4 checkout_confirm.html used ASCII-only "Dziekujemy" — Phase 5 templates must use "Dziękujemy".
4. **CSRF exemption on webhook only:** Only `/zamowienie/webhook/p24/` needs `@csrf_exempt`. The return and cancel URLs are normal GET requests and must NOT be CSRF-exempt.
5. **Checkout form resubmission:** After the checkout POST registers the P24 transaction and redirects to P24, pressing browser back button could resubmit the form. The view should check if the Order already has a `p24_session_id` and redirect to P24 again rather than creating a duplicate order.
